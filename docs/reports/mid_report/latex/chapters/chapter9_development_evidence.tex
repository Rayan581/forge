\section{Summary of Work Completed}
During the first half of the project horizon (Weeks 1 through 10), the FORGE development team completed:
\begin{itemize}
    \item \textbf{Theoretical \& Research Foundation:} Conducted a structured review of 40 sources spanning DDA, PCGRL (including player-adaptive PCGRL), flow theory, and psychometric instruments; addressed 7 of the 10 committee directives fully and 3 partially (Table~\ref{tab:action_register}).
    \item \textbf{Game Engine Implementation (Godot 4.x):} Developed a complete 2D action roguelike framework with room transitions, player movement, sword attack hitboxes, Spacebar dodge roll ($0.2$\,s dash, $0.26$\,s invulnerability, $1.0$\,s cooldown), camera trauma shake (decay rate $3.6$\,s$^{-1}$), and color-coded floating combat numbers.
    \item \textbf{Adversary Combat Behaviors:} Engineered two distinct enemy archetypes: Melee Crawler (direct pursuit and contact bite) and Ranged Pyromancer (standoff distance, kiting AI, telegraphed fireball projectile).
    \item \textbf{Procedural Generation \& AI Integration:} Engineered a two-stage decoupled generation system producing layouts that are connected by construction (BFS regression test over 3,500 layouts); implemented a pure-GDScript neural network forward pass (median $0.21$--$0.36$\,ms); and deployed a 5-floor cold-start calibration protocol that computes $CR_0 \in [10, 95]$ and seeds the first PPO observation.
    \item \textbf{Comparative Control Baseline:} Developed an in-engine toggle in the Defense Telemetry Overlay enabling real-time switching between closed-loop PPO adaptation and a deterministic $+8\%$ per-floor static roguelike baseline.
    \item \textbf{Automated CI/CD Solvability Testing:} Established a GitHub Actions pipeline on Godot 4.7.2: headless script loading, the reachability regression test, headless GDScript tests (TC-01, TC-02, TC-10), Python lint, \texttt{pytest} and policy-file validation.
    \item \textbf{Documentation Baseline:} Authored comprehensive SRS, SDS, and Mid-Evaluation reports adhering to Form 2 and Form 3 rubrics.
\end{itemize}

\section{Work Remaining for Subsequent Gates}
To maintain transparent project tracking, the work deferred to subsequent gates includes:
\begin{itemize}
    \item \textbf{Gate 3 Exit / FYP-1 Final (Weeks 11--14):} Correcting the training simulator (model aggro, scarcity, enemy count and ranged ratio; calibrate pace from playtests) and retraining the policy; comparing PPO against the heuristic fallback and the static $+8\%$ baseline; logging frame times; expanding the combat ecosystem to 5 archetypes (adding Brute, Skirmisher, and Swarmer); migrating flat JSON telemetry to SQLite; training the empirical machine-learning Judge regressor ($\text{MAE} \le 0.15$) on a 25-session corpus and integrating live polynomial TreeSHAP feature attribution in Godot.
    \item \textbf{Gate 4 / Mid-2 Evaluation (Weeks 15--26):} Implementing the in-run equipment shop economy with currency (\textit{Forge Embers}), Judge-model re-validation against the equipment-augmented gameplay, system integration testing, and non-functional performance benchmarking.
    \item \textbf{Gate 5 / Final-2 Acceptance (Weeks 27--32):} Conducting a formal 10-participant human User Acceptance Testing (UAT) study using standardized psychometric instruments (GEQ and PENS).
\end{itemize}

\section{Repository and Version Control Evidence}
Development is managed through a private GitHub repository (\texttt{Rayan581/forge}). 
\begin{itemize}
    \item \textbf{Branching Strategy:} The stable baseline lives on \texttt{main}; the five-floor calibration levels were developed on the feature branch \texttt{5levels}. The CI workflow runs on pushes to \texttt{main} and \texttt{dev} and on pull requests to \texttt{main}.
    \item \textbf{Commit Hygiene:} Recent commits use conventional-commit prefixes (\texttt{feat}, \texttt{fix}, \texttt{ci}, \texttt{docs}) and describe the change; earlier exploratory commits have shorter messages.
    \item \textbf{Release Tags:} The Mid-1 baseline is tagged in the repository:
    \begin{itemize}

    \end{itemize}

\section{Security and Privacy Considerations}
\label{sec:ethics}
Project FORGE enforces a strict \textbf{Privacy-by-Design} architecture:
\begin{itemize}
    \item \textbf{Client-Side Isolation:} All telemetry data is stored strictly in the local application directory (\texttt{user://session\_telemetry.json}). No networking sockets or cloud analytics endpoints exist in the runtime build.
    \item \textbf{Zero PII Governance:} Telemetry records contain exclusively numeric gameplay indices (time, health deltas, damage numbers). No personal identity data is captured.
\end{itemize}

\section{Current Limitations}
\label{sec:limitations}
The prototype currently has seven known limitations, scheduled for resolution in subsequent gates:
\begin{enumerate}
    \item \textbf{Adversary Diversity:} Currently implements 2 archetypes (Melee Crawler and Ranged Pyromancer). The full 5-archetype ecosystem (including Brute, Skirmisher, and Swarmer) is scheduled for Gate 3 Exit (Final-1).
    \item \textbf{Difficulty Evaluation Model:} The Judge model is currently a linear proxy with hand-set weights; it has not been validated against player data. The empirical supervised Gradient Boosted Regressor with TreeSHAP feature attribution is scheduled for Gate 3 Exit (Final-1).
    \item \textbf{Telemetry Storage Format:} Currently utilizes flat JSON files. Migration to an embedded SQLite database is scheduled for Gate 3 Exit (Final-1).
    \item \textbf{No Inter-Floor Rate Limiter:} The PPO action sets the next floor's parameters directly (within the bounds of Table~\ref{tab:param_ranges}), so a single step can change them by a large fraction of their range. A per-floor limiter and its evaluation are scheduled for FYP-2.
    \item \textbf{Partial Personalization:} In simulation the shipped policy holds enemy damage at its minimum and enemy speed at its maximum for every player, and its aggro and scarcity outputs are untrained (Section~\ref{sec:policy_params}). Retraining against a corrected simulator is scheduled for Gate 3 Exit.
    \item \textbf{Unmodelled Difficulty Settings:} The ranged-enemy ratio on PPO floors comes from the linear proxy and is not modelled by the training simulator, and the simulator's pace target ($7.5$\,s per room) has not been calibrated against real play.
    \item \textbf{Frame Rate Not Yet Measured:} NFR-05 (60\,FPS) has been observed in play but not logged on a specified test machine.
\end{enumerate}
